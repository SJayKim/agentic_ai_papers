## Problem

LLM 기반 멀티에이전트 시스템(MAS)은 복잡한 추론, 계획, 도구 활용 과제에서 강력한 성능을 보이지만, 효과적인 MAS 아키텍처를 설계하는 작업은 여전히 노동집약적이고 깨지기 쉬우며 일반화가 어렵다.
전문가가 에이전트의 역할, 상호작용 구조, 실행 로직을 일일이 명세해야 하므로 수작업 설계는 과제 간 확장이 안 되고 다양하거나 변화하는 요구사항에 적응하지 못한다.
이를 자동화하려는 기존 연구는 두 갈래로 나뉘는데 모두 한계가 있다.
첫째, ADAS나 MAS-GPT처럼 MAS를 코드 생성/오픈엔드 코드 탐색으로 정식화하는 방법은 표현력은 높지만 생성된 코드가 실행 불가(executability failure)하거나 런타임 예외로 깨지는 경우가 많다.
실제로 MAS-GPT는 SWE-Bench-Lite에서 실행 성공률(execution rate)이 1.2%, BBEH에서 71.5%에 그쳐 코드 기반 생성의 취약성을 그대로 드러낸다.
둘째, AutoAgents, EvoAgent, MetaAgent처럼 고정된 아키텍처 템플릿이나 유한상태기계 등 경직된 구조 제약을 두는 방법은 실행 신뢰성은 높이지만 표현력과 적응성이 떨어져 일반성이 희생된다.
즉 기존 자동 MAS 생성은 "표현력 vs 신뢰성"이라는 근본적 긴장 관계에 갇혀 있다.

## Motivation

핵심 직관은 MAS 생성을 코드 생성도 아니고 고정 템플릿도 아닌, "구조화된 설정(structured configuration) 생성" 문제로 정식화하면 두 마리 토끼를 모두 잡을 수 있다는 것이다.
각 설정(configuration)은 에이전트 프롬프트, 도구 접근권, 백본 모델, 에이전트 간 토폴로지를 선언적(declarative)으로 정의하고, 경량 런타임 인터프리터가 이를 해석·실행하여 시스템 구조와 실행 로직을 분리한다.
설정 생성은 직접 코드 생성보다 훨씬 견고하면서도(문법 오류·런타임 예외 제거) 넓은 MAS 설계 공간을 탐색할 수 있어, 오늘날 LLM의 능력과 잘 맞고 추론 시점(inference-time) 적응에 효율적이다.
또한 진화적 탐색은 테스트타임 컴퓨트 스케일링의 유망한 수단으로 본다.
단일 에이전트 내부에 연산을 몰아주는 대신, 설정 공간에 대한 탐색을 통해 멀티에이전트 시스템 전반에 연산을 적응적으로 분배하기 때문이다.
나아가 진화는 그래디언트 기반 파인튜닝과 구별되는 "상태 기반 학습" 패러다임을 제공하여, 설정 업데이트와 실행 경험을 통해 개선이 누적된다.

## Method

EvoMAS는 LLM을 메타모델로 사용해 설정 후보 풀(pool)에 대한 진화적 탐색을 수행하며, 실행 피드백을 학습 신호로 쓴다.
중요한 점은 설정 선택 시 정답(ground truth)에 접근하지 않고 LLM-as-judge를 대리 보상 신호로 사용한다는 것이다.

**1. 문제 정식화 (MAS Configuration).**
MAS 설정은 튜플 C = (G, {A_i}, V_in, V_out)로 정의된다.
G=(V,E)는 비순환 통신 그래프로, 에지 (v_i, v_j)는 v_i의 출력이 v_j의 입력 일부가 됨을 의미한다.
각 에이전트 A_i = (b_i, p_i, Γ_i)는 백본 모델 b_i, 시스템 프롬프트 템플릿 p_i, 도구 집합 Γ_i로 구성되며, V_in/V_out은 입력/출력 에이전트 부분집합이다.

**2. 네 가지 진화 연산자.**
유전 알고리즘 개념을 빌리되 무작위 섭동 대신 과제 맥락과 실행 피드백에 조건화된 LLM 기반 연산자를 쓴다.
(a) Select: 풀 메타데이터(과제 주석, 도메인 태그, 유사 질의의 과거 성능)를 이용해 과제 관련성 기반으로 k개의 초기 후보를 검색·인스턴스화하며, 서로 보완적인 능력(예: 하나는 분해, 다른 하나는 검증에 강함)을 가진 다양한 부모 설정을 고른다.
(b) Mutate: 단일 부모의 정확히 한 가지 컴포넌트 유형만 수정한다(프롬프트 정제, 백본 모델 재할당, 도구 목록 갱신, 또는 통신 토폴로지 재배선).
실행 트레이스를 분석해 주된 성능 병목을 찾아낸 뒤 그것을 해결하도록 설정을 갱신하며, 한 번에 한 컴포넌트만 바꿔 변화의 효과를 격리하고 체계적으로 탐색한다.
(c) Crossover: 두 부모를 재조합하되, 자식은 정확히 한 부모로부터 통신 토폴로지 전체를 상속해 구조적 일관성을 보존한다.
그 후 메타모델이 상속된 토폴로지의 각 위치에 대해 두 부모의 에이전트 수준 속성(프롬프트, 모델, 도구)을 선택·재조합한다.
(d) Consolidate: 한 진화 트레이스를 LLM으로 압축 요약하여 메모리에 저장한다.

**3. 진화 및 평가 루프.**
질의 q에 대해 k개의 초기 설정에서 시작해 최대 n 스텝 반복한다.
각 스텝에서 (1) 현재 후보 집합에서 유망한 설정을 고르고, (2) Mutate 또는 Crossover로 자식 C'을 생성하고, (3) C'을 q에 실행해 보상을 평가하고, (4) C'을 후보 집합에 추가한다.
보상은 R(q,C) = Metrics(q,C) − β·Cost(C)로 정의된다.
Metrics는 LLM-as-judge가 실행 결과와 에이전트 궤적을 정확성·완전성·추론 품질 등 과제 적합 차원에서 평가한 스칼라 점수이며, Cost(C)=T+α·L은 토큰 사용량 T와 벽시계 지연 L(α=1000)을 합친 비용이다(β는 성능-효율 균형 조절).
n 스텝 후 후보 집합은 k+n개가 되고, 보상이 가장 높은 설정 C_q를 최종 실행용으로 반환한다.

**4. 풀·메모리 업데이트(교차 질의 학습).**
질의는 순차적으로 처리되며(온라인 학습), 질의 q 완료 후 최적 설정을 풀에 추가한다(C_{t+1}=C_t ∪ {C_q}).
초기 풀 C_0는 동료심사된 인간 설계 MAS(계층형·peer-to-peer 협력 구조)로 시드된다.
진화 트레이스 O_q는 Consolidate로 요약 h_q를 만들어("프롬프트 정제로 정확도 8% 향상" 같은 패턴 추출) e_q=(q, C_q, h_q)를 메모리에 저장한다.
각 진화 스텝마다 과제 설명 유사도로 최대 3개의 경험을 검색해 메타모델에 제공함으로써, 유사 과거 과제의 성공 전략을 처음부터 재발견하지 않고 재사용한다.

## Key Contribution

1. MAS 구축을 "유연한 설정을 위한 구조화된 텍스트 생성"으로 재정식화하는 패러다임을 제시하여, 코드 생성의 취약성과 고정 템플릿의 경직성을 동시에 회피하고 견고하면서도 표현력 있는 MAS 생성을 가능케 함.
2. EvoMAS라는 LLM 주도 진화 프레임워크를 제안: 인간 설계 MAS로 시드된 후보 설정 풀을 유지하고 실행 피드백 기반 변이·교차·메모리 재사용으로 반복 정제함.
3. 토폴로지·프롬프트·모델·도구라는 모든 설정 컴포넌트를 하나의 통합 시스템으로 공동 진화(jointly evolve)시키는 점이 EvoAgent(개별 에이전트만 진화), MASS(프롬프트·토폴로지만), AFlow(순수 LLM 워크플로우)와 구별됨.
4. 풀·메모리 업데이트를 통한 교차 질의 경험 축적(cross-query experience transfer)을 도입하여 기존 방법이 결여한 누적 학습 능력을 제공.
5. 추론, 코딩, 도구 호출(BBEH, SWE-Bench, WorkBench)에 걸친 광범위한 벤치마킹으로 더 높은 과제 성능과 실행 성공률을 입증.

## Experiment & Results

**셋업.** BBEH(추론, 23개 서브태스크), WorkBench(도구 사용, 6개 도메인), SWE-Bench-Lite/Verified(소프트웨어 엔지니어링)에서 평가하며, 각 질의를 3회 반복 평균낸다.
기본 메타모델은 Claude-4-Sonnet, 에이전트 백본 풀은 Claude-3.5-Sonnet, Qwen3-235B, Qwen3-Coder-480B이다.
베이스라인은 Direct LLM Call, Single Agent, 인간 설계 MAS(Peer Review, Croto, SMoA, Multi-Agent Debate, Majority Vote, MetaGPT, ChatDev), 자동 생성 방법(AutoAgents, EvoAgent, MAS-GPT, ADAS)이다.
1) BBEH: EvoMAS(LLM 자동 선택)가 58.7% 정확도로, 최고 단일 LLM 변형(Qwen3-235B 52.8%)보다 +5.9점, 진화 베이스라인 EvoAgent 최고치(48.2%)보다 +10.5점 우위.
2) WorkBench: 48.9%로 최고 단일 LLM(44.5%)보다 +4.4점, EvoAgent보다 +7.1점.
3) SWE-Bench-Verified: 63.8%로 최고 단일 LLM(Qwen3-480B 60.4%)보다 +3.4점, Single Agent(56.4%)보다 +7.4점.
4) 실행 성공률: BBEH 98.9%, WorkBench 98.5%, SWE-Bench-Verified 98.4%로 매우 높은 반면, MAS-GPT는 BBEH 71.5%, SWE-Bench-Lite 1.2%에 불과.
5) 인간 설계 MAS 대비: BBEH에서 58.7% vs Peer Review 46.2%(+12.5점), SWE-Bench-Verified에서 63.8% vs MetaGPT 40.9%.
6) 최신 모델(Claude-4.5-Sonnet): SWE-Bench-Verified에서 79.1% 달성, 작성 시점 공개 리더보드 최고치(78.8%, 더 큰 모델·특수 모델·스캐폴딩 사용)를 근소하게 상회.
7) 추가로 AIME 2024–2025 수학 추론에서 56.7%로 최고 인간 설계 MAS(Peer Review 51.7%)를 상회.

**분석/어블레이션.**
고품질 시드 풀이 핵심(빈 풀 대비 +15.6점)이며, 진화 깊이는 T=3(BBEH-Mini 49.1%)이 T=5(47.6%)보다 우수해 과도한 반복은 수확체감.
교차 질의 누적 없이 질의별 진화만으로도 40.4% vs 단일 에이전트 36.6%로 베이스라인을 능가(제로샷에서도 유효).
동등 예산 비교(SWE-Bench-Verified)에서 EvoMAS는 29M 토큰으로 42.7%를 달성해, 40M 토큰을 쓰는 Best-of-10+selection(37.8%)을 능가 — 이득이 단순 반복·앙상블이 아닌 구조적 발견에서 옴을 입증.
메타모델 민감도: 가장 약한 메타모델(Claude-3.5-Sonnet)조차 모든 베이스라인을 상회하고, 메타모델 오버헤드는 토큰의 7.7%·시간의 10.6%로 제한적이며 풀은 약 300–400 질의 후 안정화되어 초기 진화 비용이 분할상환된다.
오라클 보상은 LLM-judge 대비 +1.5~3.4점의 작은 이득만 주어 정답 없는 보상 추정이 효과적임을 확인했고, 진화된 설정에서 모델-역할 친화성·전용 검증자/분해자 출현·에이전트 수 ~70% 감소 같은 창발적 패턴이 관찰됐다.

## Limitation

저자가 명시한 한계로, 본 연구는 협력적(cooperative) MAS만 다루며 상충하는 목표를 가진 적대적(adversarial) 에이전트 조정은 고려하지 않았다(향후 과제로 제시).
또한 진화 비용 절감이 미해결 과제로 남아 있으며, 핵심 설계 원칙이 "추론 시점 연산을 더 들여 더 나은 결과를 얻는" 것이므로 EvoMAS는 지연(latency)보다 정확도가 우선시되는 환경을 겨냥한다 — 즉 실시간·저지연 응용에는 부적합하다.
독자 관점에서 보면, 평가가 LLM-as-judge라는 대리 보상에 의존하므로 판정자 편향이 진화 방향을 왜곡할 위험이 있다(저자는 오라클과의 작은 격차로 방어하나 과제 의존적일 수 있음).
풀이 안정화되기까지 300–400개의 질의가 필요하다는 점은 소규모·콜드스타트 배포에서 초기 비용 부담이 크다는 실제적 영향을 시사한다.
나아가 비순환(acyclic) 통신 그래프로 토폴로지를 제한하므로 순환적 반복 협업 패턴은 구조적으로 표현하기 어렵고, 도구 집합 등은 사전 정의된 행동 공간 내에서만 진화하므로 진정한 오픈엔드 도구 발견은 제한된다.
