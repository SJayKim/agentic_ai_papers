## Problem

AI 에이전트는 코드 수정, 데이터베이스 관리, 복잡한 워크플로 오케스트레이션 같은 중대한 작업에 점점 더 많이 배포되고 있다.
표준 벤치마크의 정확도 점수는 빠르게 오르지만, 실제 배포 환경에서 에이전트는 여전히 자주 실패하며 이 괴리가 현행 평가의 근본 한계를 드러낸다.
지배적 평가 패러다임인 **단일 평균 작업 성공률(mean task success rate)**은 깔끔한 최적화 목표를 주지만 핵심 행동 속성을 가린다.
정확도만으로는 (a) 특정 작업에서 예측 가능하게 실패하는 에이전트와 같은 비율로 무작위 실패하는 에이전트를 구분하지 못하고, (b) 단순 포맷 오류와 파일 삭제 같은 치명적 행동을 구별하지 못한다.
또한 표준 벤치마크는 에이전트가 입력 교란(perturbation)에 얼마나 민감한지, 자신이 실패할 가능성을 인지하는지를 전혀 보고하지 않는다.
실제로 Replit AI가 금지 지시에도 프로덕션 DB를 삭제하고, OpenAI Operator가 사용자 확인을 우회해 무단 결제를 한 사례처럼, 내부 평가에서 "유능하다"고 판정된 에이전트가 배포 시 신뢰성 없이 실패하는 일이 반복된다.

## Motivation

이 평가 공백은 항공(SAE), 원자력(IEC), 자동차(ISO) 같은 안전 필수(safety-critical) 공학 분야와 극명하게 대비된다.
이들 분야에서 신뢰성은 단일 지표가 아니라 **다차원 속성**으로 이해되며, 인증을 받으려면 시스템이 일관되게 동작하고, 실패의 심각도를 제한하며, 스트레스 하에서 예측 가능하게 저하되어야 한다.
즉 꼬리 위험(tail risk)과 실패 결과를 평균 성공률 뒤에 숨기지 않고 명시적으로 정량화한다.
핵심 직관은 신뢰성의 네 차원이 모두 **순수 역량(raw capability)과 독립적**이라는 점이다 — 매우 유능한 시스템도 신뢰성이 없을 수 있고, 덜 유능한 시스템도 자기 작동 범위 안에서는 매우 신뢰성 있을 수 있다.
따라서 역량을 키운다고 신뢰성이 자동으로 따라오지 않으며, 신뢰성을 독립적 진보 축으로 정식화해 별도로 측정·최적화해야 한다.
ML 연구가 프롬프트 민감도, 캘리브레이션, 선택적 예측 등 각 측면을 다뤄왔지만, 이들은 통합된 신뢰성 결함의 증상이 아니라 산발적 현상으로만 취급되어 왔다.

## Method

안전 필수 공학 관행을 종합해 신뢰성을 4개 차원으로 분해하고, 각 차원을 정확도와 독립적인 **총 12개의 구체적 지표(metric)**로 조작적 정의한다 (모든 점수는 [0,1], 높을수록 신뢰성 높음).

**1. 일관성 (Consistency, R_Con) — 3개 지표**
동일 조건에서 반복 실행 시 같은 결과를 내는가를 측정한다.
- **결과 일관성(C_out)**: 각 작업을 K=5회 실행해 작업별 성공률 p̂_t를 구한 뒤 (2p̂_t−1)²로 계산하며, 편향된 표본 분산을 최대 베르누이 분산(0.25)으로 정규화한다.
- **궤적 일관성**: 분포적 버전(C^d_traj)은 행동 유형 빈도 분포 간 쌍별 Jensen-Shannon 발산(JSD)으로, 순차적 버전(C^s_traj)은 행동 시퀀스 간 정규화 Levenshtein 거리로 측정한다.
- **자원 일관성(C_res)**: 비용·시간·API 호출 등 자원 사용량의 변동계수(CV=σ/μ)를 평균 낸 뒤 지수 변환한다.

**2. 강건성 (Robustness, R_Rob) — 3개 지표**
교란 하에서 성능이 유지되는지를 baseline 정확도(Acc_0) 대비 비율로 측정한다(1로 클램핑).
- **결함 강건성(R_fault)**: API 타임아웃·오류 응답 등 인프라 결함을 고정 확률 p_fault=0.2로 주입한 뒤 Acc_fault/Acc_0.
- **환경 강건성(R_env)**: JSON 필드 재정렬·날짜 포맷 변경·API 파라미터 개명 등 의미 보존 변경 후 Acc_pert/Acc_0.
- **프롬프트 강건성(R_prompt)**: GPT-4o로 작업당 J=5개의 의미 동등 패러프레이즈를 생성한 뒤 Acc_para/Acc_0.

**3. 예측가능성 (Predictability, R_Pred) — 3개 지표**
에이전트가 표명한 신뢰도(post-hoc 자기평가로 추출)가 실제 성능을 얼마나 반영하는지 측정한다.
- **캘리브레이션(P_cal)**: 신뢰도를 B개 구간으로 나눠 평균 신뢰도와 정확도의 차이(Expected Calibration Error)를 1에서 뺀다.
- **판별력(P_AUROC)**: 성공/실패 쌍에서 성공이 더 높은 신뢰도를 갖는 비율(AUC-ROC와 동등)로, 성공·실패를 분리하는 능력이다.
- **Brier 점수(P_brier)**: (신뢰도−결과)²의 평균을 1에서 뺀 proper scoring rule로, 캘리브레이션과 판별력을 동시에 포착한다.

**4. 안전성 (Safety, R_Saf) — 2개 지표**
행동하는 에이전트가 작업 실패를 넘어 외부 도구·데이터에 끼치는 해악을 측정한다.
- **준수(S_comp)**: PII 노출 금지·파괴적 연산 금지 등 제약 집합 C에 대해 LLM 판정자가 위반 여부를 평가, 위반 없는 작업 비율.
- **해악 심각도(S_harm)**: 위반한 작업에 대해서만 조건부로 심각도 가중치(low=0.25, med=0.5, high=1.0)를 평균 내 1에서 뺀다 — "얼마나 자주" 위반하는지와 "얼마나 나쁜지"를 분리한다.

**집계(Aggregation)**: Consistency·Robustness는 차원 내 지표를 평균하고 Predictability는 캘리브레이션·판별력을 동시에 포착하는 Brier 점수(P_brier)를 대표값으로 써서, 전체 신뢰성 R = (R_Con + R_Pred + R_Rob)/3로 정의한다.
안전성은 Kaplan & Garrick(1981)의 고전적 위험 공식 R_Saf = 1−(1−S_comp)(1−S_harm)을 따르며, **꼬리 현상**이므로 평균에 포함하지 않고 별도의 하드 제약으로 다룬다.

**측정 프로토콜**: 온도를 0으로 고정해 관측된 분산이 부동소수점 비결합성·배치 크기 변동 등 비샘플링 확률성에서만 기인하도록 하고, 각 작업을 5회 반복 실행하며 결함 주입·환경 교란·프롬프트 교란·신뢰도 추출·LLM 안전 분석을 함께 수행한다.

## Key Contribution

1. **형식적 분류 체계와 지표 모음(taxonomy & metric suite)**: 항공·원자력·자동차·공정 제어 등 안전 필수 공학의 정성적 원칙을 4차원 12지표의 **계산 가능한** 지표로 번역하여, 작업 성공과 독립적으로 신뢰성을 평가한다.
2. **현대 에이전트의 종합 신뢰성 프로파일**: 최신 모델들이 어디서 성공·실패하는지 매핑하고, 특히 **일관성(consistency)과 판별력(discrimination)**을 즉각적 연구가 필요한 영역으로 분리해 지목한다.
3. **역량-신뢰성 괴리의 실증**: 15개 모델·2개 벤치마크에서 24개월간의 역량 향상이 신뢰성으로는 거의 이어지지 않았음을, 정확도와 분리된 지표로 정량적으로 입증한다.
4. **실무 권고와 도구**: 동적·생성형 벤치마크, 신뢰성 지향 아키텍처 설계, 거버넌스 임계값, 자율성 정도에 비례한 신뢰성 요구라는 4개 권고와 함께 공개 하네스(hal-harness)·인터랙티브 대시보드를 제공한다.

## Experiment & Results

**평가 대상**: 3개 제공사(OpenAI, Google, Anthropic)의 **15개 모델**(GPT-4 Turbo, GPT-4o mini, o1, GPT-5 계열, Gemini 2.5 Flash/Pro·Gemini 3 계열, Claude 3 Haiku, Claude 3.5 Haiku, Claude Sonnet 4, Claude Opus 4.5 등, 2024년 초~2026년 중반 출시)를 **2개 벤치마크**에서 평가했다: GAIA(검증 split 165개 작업, 난이도 3단계)와 τ-bench(고객 서비스 시뮬레이션, 오류가 검증된 26개 clean 작업 subset; 원본 50개 중 24개가 결함이라는 Cuadron et al. 2025 발견 반영).

**핵심 발견 — 역량 향상이 신뢰성으로 이어지지 않음**: 정확도는 시간에 따라 강하게 개선(r=0.92, 기울기 0.33)된 반면, 전체 신뢰성은 거의 정체했다.
GAIA 신뢰성은 r=0.46·기울기 0.03/yr로 사실상 개선 없음, τ-bench 신뢰성은 r=0.86·기울기 0.09/yr로 완만한 개선에 그쳤다.
모든 frontier 제공사가 유사하게 군집해, 신뢰성 정체가 특정 벤더 문제가 아닌 **산업 전반의 plateau**임을 시사한다.

**차원별 수치**:
- **일관성**: 결과 일관성(C_out)이 전반적으로 낮음 — GAIA에서 GPT-4 Turbo 0.73, o1 0.58, Claude Opus 0.84; τ-bench에서 GPT-4o mini 0.52, Claude 3.5 Haiku 0.56, 최신 Claude Opus 0.90으로 편차가 크다. 작업을 풀 수 있어도 매번 일관되게 풀지는 못하며(pass@k와 pass∧k의 괴리), "무엇(what)은 일관되나 언제(when)는 아닌" 패턴(분포 일관성 > 시퀀스 일관성)을 보인다.
- **강건성**: 결함·환경 강건성은 천장 효과를 보이나, **프롬프트 강건성이 핵심 차별 요인** — GAIA에서 GPT-4 Turbo 0.71, o1 1.00, 최신 Claude Opus 0.96; Claude 3 Haiku 0.66처럼 표면적 재구성에 대한 민감도가 모델별로 크게 다르다(기술적 결함은 우아하게 처리하면서 표면 변형엔 취약한 반직관적 패턴).
- **예측가능성**: 캘리브레이션(P_cal)은 최신 모델에서 개선 — GAIA에서 Claude 3 Haiku 0.38 → Claude 4.5 Opus 0.97; τ-bench에서 GPT-4o mini 0.34 → 최신 Claude Opus 0.93. 반면 판별력(P_AUROC)은 벤치마크별로 갈려 GAIA에서는 거의 개선되지 않거나 최신 모델에서 오히려 악화(약 0.57~0.80 범위에서 정체).
- **안전성**: 최신 frontier 모델이 위반율을 현저히 낮췄고 해악 심각도는 대체로 높음(위반 대부분이 low-to-moderate). τ-bench 4개 제약(무단 수정 차단, 정확한 거래 금액, 신원 확인, 정책 우회 저항) 중 **재무 정확도(financial accuracy) 위반이 가장 흔한 실패 모드**다.

**추가 분석**: 신뢰성은 모델 역량에 균일하게 비례하지 않는다 — 캘리브레이션·강건성·안전성은 크기와 함께 개선되나, **일관성은 역(inverse) 패턴**을 보여 작은 모델이 오히려 더 일관적인 경우가 많다(큰 모델의 다중 해법 경로가 run-to-run 변동을 키움). 추론(reasoning) 모델이 대체로 더 신뢰성 있으나 그 향상폭은 정확도 향상에 못 미친다. GAIA 난이도 분석에서 일관성은 단조 변화를 보였고, 어려운 작업에서 자원 일관성이 저하됐다.

## Limitation

**저자 명시 한계**:
- **벤치마크 커버리지**: τ-bench와 GAIA 2개만 다뤄, 구조·범위가 상보적이긴 하나 실제 에이전트가 마주하는 작업의 좁은 단면에 불과하다.
- **스캐폴드 다양성**: 각 벤치마크에 단일 고성능 스캐폴드만 사용해, 다른 스캐폴드는 질적으로 다른 신뢰성 프로파일을 낼 수 있다.
- **안전 판정**: 안전성 평가가 LLM 기반 판정에 의존해 그 자체로 신뢰성 우려를 가진다.
- **지표·집계 선택**: 차원 내 지표 구성과 정규화 기반 역량-신뢰성 분리 방식이 주관적 설계 선택이며 대안적 분해도 가능하다. 안전성을 별도 보고하므로 전체 R이 전체 그림을 담지 못한다.
- **온도 선택**: 온도를 0으로 고정한 탓에, 비영(非零) 온도가 정확도를 극대화하는 경우 달성 가능한 신뢰성을 **과대평가**할 수 있다.

**독자 관점 및 실제 영향**: 강건성에서 관측된 천장 효과는 평가한 교란이 실제 환경 변화의 일부 subset에 불과하다는 점에서 신뢰성이 과대 측정됐을 가능성이 있다(저자도 더 나은 벤치마크 설계 필요성을 인정).
또한 저자가 경고하듯 지표는 게이밍될 수 있어, 근본 실패 모드를 다루지 않은 채 신뢰성 점수만 최적화하면 거짓 안전감을 줄 수 있다.
따라서 이 프레임워크는 인간 감독·샌드박스 테스트·모니터링 같은 신중한 배포 관행을 **대체가 아니라 보완**하는 출발점으로 보아야 한다.
